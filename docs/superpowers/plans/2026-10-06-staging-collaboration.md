## Verified starting point and decisions for review

Inspected current source on 2026-10-06. `BuildChannel` already separates Folio Staging identity/storage with `FOLIO_STAGING`. `ReaderModel.documentID` is a transient UI generation identity; it must not become the shared document UUID. `save(asCopy:) -> Bool` currently writes through `DocumentSnapshot.save`, then updates baseline. `reload()` preserves dirty text but `startMonitor()` observes only modification date/size once per second. `render()` rotates the highlight token and reloads private marks. `SavedHighlight` contains `id/start/quote/prefix/suffix/comment/revision`; its offsets are rendered-text UTF-16 and its revision is SHA-256 of decoded-source UTF-8, not raw file bytes. `TaskListEdit.setChecked(_:atUTF16:in:)` targets a source UTF-16 checkbox offset. These coordinate spaces must remain explicit.

The prototype exposes `ReplicaStore.enqueue/reconcile/publishOutbox/exportEvidence` and `SourceRecovery.prepare/load/apply/outcome/recover`. It has schema-1 `comment/task/sourceProposal/sourceResolution` payloads only. `ReplicaStore.document()` requires exactly one disposable source; initialization creates `fixture.md`; `SourceRecovery` uses that singleton and its state aggregates source heads across documents. None can be transplanted unchanged into the app.

Prior recorded evidence: prototype 28 tests passed after independent review; basic two-way OneDrive file delivery confirmed. Full source conflict/recovery, actual shared-app UI, Files On-Demand and multi-document integration remain unverified. No tests or app acceptance are claimed by this plan.

Proposed decisions to accept/change during written-plan review:

- Reuse protocol algorithms in `Sources/ReaderCore/Collaboration/`, leaving `experiments/CollaborationTransport` unchanged as reviewed reference. Do not add the probe executable or experiment package as an app dependency.
- Use a new schema-2 workspace inside a **fresh disposable pilot child**, not the existing schema-1 experiment folders. Reject schema-1 join with an explicit explanation; no silent conversion. Shared layout remains `Folio Review/workspace.json`, `documents/<UUID>.json`, `events/<UUID>.json`, `snapshots/<rawSHA256>.bin`.
- Pilot envelope: one watched workspace, at most 8 registered documents; keep prototype candidate limits (64 KiB event, 8 MiB snapshot, 16 KiB manifest, 2,000 distinct events including pending, 256 snapshots, 128 MiB admitted bytes, 5,000 candidate files across shared/received/outbox/conflicts, 32 parents/supersedes, 8,000 UTF-8 comment bytes, 100 retained diagnostics plus counts). Bound workspace enumeration to 5,000 candidates too. These are pilot limits, not qualified product limits; freeze only after actual measurements.
- Each event carries an immutable display-name snapshot alongside participant/device IDs. Renaming affects future events only; no shared mutable profile file or authentication implied.
- Newly shared annotations must refer to the currently saved source revision. If the document is dirty, offer guarded Save first or a private mark. Existing private marks can be shared explicitly per document, with a preview and no private journal upload; stale/ambiguous marks need reattachment first.
- Stable document UUIDs come from explicit registration by the creator. Immutable manifests contain initial relative path and initial raw revision; current path bindings are local. The replica source lookup consumes that verified local binding, never an unchecked URL from a callback. Preserve a local rename only when the same recorded resource identity uniquely proves it; otherwise ask each Mac to reconnect the existing UUID. A new/copied Markdown file stays unregistered until explicitly added. Never rewrite an existing identity manifest or silently assign a copy the original UUID.
- Shared review is available in Staging preview; guarded source save is separately opt-in during the disposable pilot. If conflict recovery fails, disable shared source saving and keep the gate failed; a review-only public scope would need separate approval.

Core contracts (each owning task defines the listed types before dependent tasks use them):

- `ParticipantProfile: Codable, Equatable { participantID: UUID, deviceID: UUID, displayName: String }`; `ParticipantStore.loadOrCreate(displayName: String) throws -> ParticipantProfile`; `rename(to: String) throws -> ParticipantProfile`.
- `SharedDocumentRef: Codable, Equatable { workspaceID: UUID, documentID: UUID, relativePath: String }`; manifest keeps initial binding separate from this current local binding.
- `SharedAnchor: Codable, Equatable { start: Int, quote: String, prefix: String, suffix: String, rawSourceRevision: String, decodedSourceRevision: String }`; `start` is rendered UTF-16. Limits reuse quote 20,000 UTF-16 units and context 64 each from `SavedHighlight`.
- `CollaborationEvent` uses schema 2 and the prototype envelope plus `authorName: String` and `rawSourceRevision: String` (the exact saved bytes reviewed when the action was authored; source proposals use their base revision). Payloads: `highlightAdded(highlightID: UUID, anchor: SharedAnchor)`, `highlightRemoved(highlightID: UUID, supersedes: [UUID])`, `highlightReattached(highlightID: UUID, anchor: SharedAnchor, supersedes: [UUID])`, `commentAdded(threadID: UUID, messageID: UUID, replyTo: UUID?, text: String)`, `threadState(threadID: UUID, resolved: Bool, supersedes: [UUID])`, `taskRegistered(taskID: UUID, anchor: SharedTaskAnchor)`, `taskState(taskID: UUID, state: SharedTaskState, supersedes: [UUID], rawSourceRevision: String)`, `sourceProposal(baseRevision: String, proposedRevision: String, triggerEventID: UUID?)`, `sourceResolution(baseRevision: String, proposedRevision: String, supersedes: [UUID])`. The thread UUID is its highlight UUID; reply dependencies identify messages, with their creating event in causal parents. `SharedTaskState` is `open/inProgress/done`.
- `CollaborationState` holds accepted/pending/invalid event IDs, missing snapshots, annotations/messages/thread heads, task heads and **source heads indexed by document UUID**. `CollaborationReducer.reduce(events:snapshots:) -> CollaborationState` never uses display time to resolve heads.
- `CollaborationReplicaStore(localRoot:sharedRoot:workspaceID:limits:)`; `createWorkspace() throws`, `join() throws`, `registerDocument(relativePath: String, initialBytes: Data) throws -> SharedDocumentRef`, `document(id: UUID) throws -> SharedDocumentRef`, `reconnectDocument(id: UUID, relativePath: String) throws -> SharedDocumentRef`, `enqueue(_:snapshots:) throws`, `reconcile() throws -> CollaborationReport`, `publishOutbox() throws -> CollaborationPublishReport`, `exportEvidence(to:) throws`. `CollaborationReport` contains `status`, optional complete `state`, `diagnostics`, `diagnosticCount` and per-document blocking IDs; `CollaborationPublishReport` contains `status`, `materialized` and the local-only guarantee. Use prototype status cases; whole-workspace identity/capacity loss blocks all writes. Report includes immutable origin/received IDs and complete/incomplete coverage.
- `SharedTaskAnchor: Codable, Equatable { sourceOffsetUTF16: Int, line: String, prefix: String, suffix: String, rawSourceRevision: String, decodedSourceRevision: String }`; `SharedTaskMatcher.locate(_:in:) -> Int?` requires unambiguous checkbox line plus context, never a text hash alone.
- `CollaborationSourceRecovery.prepare(document:base:proposed:actor:parents:triggerEventID:store:) throws -> PreparedSharedSource`; `apply(_:store:) throws -> SharedApplyResult`; `prepareResolution(document:expectedCurrent:chosen:superseding:actor:store:) throws -> PreparedSharedSource`; `recover(proposalID:from:to:) throws -> SharedRecoveryExport`. Actor is `ParticipantProfile`; snapshots are exact `Data`; prepared record contains event and document identities. `SharedApplyResult` mirrors `applied/unchanged/conflict/unavailable` and preserves phase receipts. `SharedRecoveryExport` contains proposal ID, snapshot hashes/paths, local receipt or `intendedOnly`, `externalRecoveryGap` and coverage. `SharedSaveOutcome` contains proposal ID, local apply result and publication state; failure is thrown and never turns into success.
- `@MainActor CollaborationCoordinator` owns published workspace/review/status state; `join(folder: URL, create: Bool) async throws`, `submit(document:payload:parents:snapshots:) async throws -> UUID`, `refresh() async`, `save(document:baseline: DocumentSnapshot, draft: String, triggerEventID: UUID?) async throws -> SharedSaveOutcome`, `stopWatching()`. Outcomes distinguish local apply, publication pending, conflict, unavailable and interrupted unknown; none means remote receipt.
