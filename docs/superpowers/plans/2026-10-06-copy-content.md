# COL-10 implementation plan: Copy content

Scope: independent COL-10 only. Base: `/Users/philip.scholl/_WORK/markdown-reader`. Copy the complete current Markdown source including unsaved accepted edits. Preserve authored Markdown, code, task markers and line endings; append no Folio comments, highlight records or edit history. Do not strip comments/front matter authored in the Markdown itself. Existing Copy Formatted Text, code-copy and Export Feedback remain unchanged. Copy does not save, render, change selection or alter undo history.

Verified baseline: `ReaderModel.text` is authoritative accepted Markdown. `web/editing.js` commits on each `input` using its existing `serializeDocument` and protected-node checks, sending `editDocument`; `ReaderModel.acceptRenderedEdit` validates token/before/size. There is currently **no explicit flush API or composition lifecycle tracking**. `ReaderModel.script` returns void and cannot acknowledge synchronization. `MarkdownEditor.Coordinator.textDidChange` forwards `NSTextView.string` immediately. `flushEditJournal` flushes history, not the editor, so it cannot establish content freshness.

**Execution:** Subagent-driven implementation, followed by independent review.

**Spec:** `../specs/2026-10-06-collaboration-design.md`

## Task 1 — Add a request-bound editor snapshot handshake

Paths: `web/editing.js`, `web/reader.js`, `Sources/MarkdownReader/ReaderWebView.swift`, `Sources/MarkdownReader/ReaderModel.swift`, `Sources/MarkdownReader/MarkdownEditor.swift`.

- Add an editor controller returned by `setupEditing`, with `requestContent(requestID)` and cleanup/cancellation. Read mode returns the untouched source. Write mode runs the existing `commit` serializer, then sends `contentReady {requestID, token, text}` only on successful commit. Make commit report rejection rather than allowing success after `editingRejected`. Expose `window.Folio.requestContent(requestID)` in `web/reader.js`; replace the controller on render and cancel any pending request during cleanup.
- Track `compositionstart`/`compositionend` on the rendered editor. A request during composition waits. After composition ends, schedule flush after the final input event, commit, then acknowledge. Do not blur, render or force composition to end. Keep existing edit behavior outside this small deferral mechanism. In complex/link Apply dialogs, reject Copy with “Apply or cancel the open edit before copying.” rather than copying source that excludes that visible draft; do not auto-apply a modal draft.
- Add `ReaderModel.copyContent()` and `@Published` busy/success state. Each request captures a UUID, `documentID`, mode and `highlightToken`; only one pending request. ReaderWebView forwards the new snapshot message. Accept it only if the pending UUID/token/document/mode still match and acknowledged text equals the current `model.text` after normal `editDocument` processing. An unmatched current-text snapshot is a visible synchronization failure, never a fallback to older text. Test ordering of edit and snapshot delivery in real WKWebView. The new evaluated JS call needs its own completion error handling; the existing void `script` alone cannot prove the request was dispatched successfully.
- Before publishing copy state, protect `MarkdownEditor.updateNSView` from replacing newer or marked native text with an older model value. Unrelated busy/success updates must not clear composition, selection or undo. Add a test that drives this exact representable-update path with native text newer than the model.
- Source mode: require the actual `model.editor`; check `hasMarkedText()`. If composing, wait for the source coordinator's post-change callback after marked text clears (dispatch to the next main-loop turn), then resynchronize through `sourceEditorDidChange(editor.string)` and copy that exact current text. If source mode has no editor, fail visibly. A request cannot substitute stale model text.
- Cancel pending requests on document replacement, mode change, render-token replacement, WebKit termination, and editor teardown; show an actionable retry message where still relevant. Cancellation invalidates the UUID before any late callback. A 15-second timeout produces an error without copying and invalidates the request; it must never force an IME commit. Do not block the main thread while waiting.

## Task 2 — Write the clipboard and expose the labeled toolbar action

Paths: `Sources/MarkdownReader/ReaderModel.swift`, `Sources/MarkdownReader/ReaderView.swift`.

- Add a small injectable pasteboard writer (default NSPasteboard.general) returning Bool; clear clipboard types and call `setString(source, forType: .string)`. Only a true result produces a brief “Copied” status. False produces “Couldn’t copy the content. Try again.” and leaves success false. Clipboard write failure can clear previous clipboard content; do not claim it was preserved.
- Empty document policy: show “The document is empty. There’s nothing to copy.” and leave the clipboard untouched. Whitespace-only content is valid and copied byte-for-byte. No Markdown normalization or size limit below the existing `DocumentReader.maximumBytes`.
- Add `Button("Copy content") { model.copyContent() }` as the trailing `.primaryAction` item, with a visible text label rather than iconOnly. Keep its exact label during pending/success states and present “Copied” separately for 1.5 seconds with accessibility announcement. Disable while loading/preparingPrint or a request is pending. Follow the existing native theme/accent styling and toolbar overflow; verify the action remains named and reachable in a narrow window.
